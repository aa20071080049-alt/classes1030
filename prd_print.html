管理系統

版本 1.0（初步需求版）　｜　2026 年 10 月 30 日

1. 產品概述

1.1 產品願景

提供個人與團隊共用的行程及任務工作區，協助成員掌握自己的待辦與受邀行程，並讓管理者有效指派工作、追蹤進度及協調團隊時間。

1.2 問題與機會

個人工作、團隊任務與共享行程分散時，成員容易忽略期限、指派內容或會議邀請狀態。產品將行事曆、任務清單、負責人、截止日期、進度及邀請回覆集中於同一工作區。

1.3 目標使用者

  • 管理者：管理團隊工作，建立並指派團隊任務，建立共享行程及邀請參與者。
  • 團隊成員：檢視自己參與或被指派的項目、建立個人任務、更新自己負責任務進度、回覆行程邀請。

2. 目標與非目標

2.1 產品目標

  1. 讓使用者快速掌握個人行程、受邀行程及任務。
  2. 讓管理者能將團隊任務指派給負責人並追蹤狀態。
  3. 讓行程建立者邀請成員，並檢視接受、婉拒或待回覆狀態。
  4. 透過系統內通知及電子郵件傳達指派與邀請等重要事件。

2.2 第一版非目標／尚未確認

  • 即時通訊、檔案協作、專案甘特圖或複雜工作流程。
  • 外部行事曆（Google／Outlook）同步。
  • 重複任務、週期行程、時區及多團隊管理策略。
  • 電子郵件通知服務的供應商、退信處理與偏好管理細節。
  • 進階分析報表與自訂角色權限。

3. 角色與權限

能力管理者成員
檢視自己參與或被指派的項目是是
建立個人任務是是
建立／指派團隊任務是否（由管理者指派）
更新自己負責任務的進度是是
建立共享行程並邀請成員是是（初步假設，待確認）
回覆行程邀請是是
管理團隊成員與角色是（初步假設，待確認）否

可見性原則：成員預設只看自己參與或被指派的項目，不得因團隊共享而自動取得檢視所有成員私人內容的權限。管理者是否可檢視全團隊所有項目需另行確認。

4. 核心功能需求

4.1 工作區總覽

  • 顯示本週行程、今日安排及我的任務。
  • 提供任務完成進度摘要。
  • 支援按日期瀏覽週行事曆。
  • 可從總覽快速新增任務或行程。
  • 任務與行程可點選檢視詳細資訊。

4.2 任務管理

  • 任務欄位至少包含：名稱、類型（個人／團隊）、負責人、截止日期、狀態。
  • 任務狀態：未開始、進行中、已完成。
  • 成員可建立個人任務；成員不得將團隊任務指派給他人。
  • 管理者可建立團隊任務並指派負責人。
  • 負責人可更新自己任務的狀態。
  • 支援按「全部」、「指派給我」、「個人任務」等條件篩選（篩選條件可在後續驗收確認）。
  • 已完成任務應有明確視覺區別。

4.3 行程管理與邀請

  • 行程至少包含：名稱、日期、開始時間、結束時間、建立者、參與者及回覆狀態。
  • 行程建立者可邀請團隊成員。
  • 受邀者可回覆：接受、婉拒或維持待回覆。
  • 建立者可查看參與者及各自回覆狀態。
  • 行程需呈現在週行事曆與每日安排中。
  • 行程邀請或變更應通知受影響的參與者（變更通知規則待確認）。

4.4 通知

  • 支援系統內通知及電子郵件通知。
  • 任務指派與行程邀請均需透過兩種方式通知（依已確認需求）。
  • 通知內容需包含事件、相關任務／行程、發起人及必要的期限／時間資訊。
  • 提醒頻率、通知偏好、重複送達與失敗重試規則待確認。

4.5 團隊與成員

  • 顯示團隊及其成員基本資料與角色。
  • 初步原型包含邀請成員入口；正式邀請方式（電子郵件、連結、網域）待確認。
  • 成員新增、移除、角色變更及離隊後資料處理方式待確認。

4.6 搜尋與導覽

  • 導覽至少包含總覽、行事曆、任務、團隊成員、收件匣及設定入口。
  • 可搜尋任務與行程名稱。
  • 行動裝置需提供適合小螢幕的導覽及內容呈現。

5. 主要使用流程

5.1 管理者指派團隊任務

  1. 管理者開啟「新增任務」。
  2. 填寫名稱、類型、負責人、截止日期及狀態。
  3. 建立後，系統將任務指派通知送至系統內通知及電子郵件。
  4. 負責人檢視任務並更新狀態。
  5. 任務完成後，總覽及任務清單顯示完成狀態。

5.2 成員建立個人任務

  1. 成員新增任務並選擇個人任務。
  2. 填寫名稱、截止日期及初始狀態。
  3. 任務加入該成員的任務清單；不可指派給其他人（權限規則待確認是否需於 UI 隱藏非本人負責人選項）。

5.3 建立共享行程與回覆邀請

  1. 建立者新增行程並選擇日期、時間及參與者。
  2. 系統建立行程，參與者狀態初始為待回覆。
  3. 系統向受邀者發送系統內通知及電子郵件。
  4. 受邀者接受或婉拒；建立者可查看每位參與者回覆。
  5. 行程顯示於相關使用者的行事曆；婉拒者是否仍顯示及其呈現方式待確認。

6. 資訊架構與主要畫面

  1. 總覽：本週行程、今日安排、我的任務、進度摘要、快速新增。
  2. 行事曆：週檢視、行程詳情、邀請回覆與參與者狀態。
  3. 任務：任務清單、狀態、負責人、截止日、篩選與新增。
  4. 團隊成員：成員清單、角色及邀請入口。
  5. 收件匣：任務指派、行程邀請及期限提醒。
  6. 設定：通知方式及個人／工作區偏好。

7. 資料概念（初步）

User

  • id、姓名、電子郵件、角色、團隊關聯、帳號狀態

Team

  • id、名稱、建立者、成員清單、建立時間

Task

  • id、名稱、描述（待確認）、類型、建立者、負責人、參與者（待確認）、截止日期、狀態、建立／更新時間

Event

  • id、名稱、描述（待確認）、建立者、開始／結束時間、時區、參與者、位置／連結（待確認）、建立／更新時間

InvitationResponse

  • event_id、user_id、狀態（待回覆／接受／婉拒）、回覆時間

Notification

  • id、收件者、通知類型、關聯項目、渠道（系統／電子郵件）、讀取狀態、建立時間、送達狀態

8. 非功能需求

  • 安全與隱私：伺服器端強制執行角色與項目可見性驗證，不可只依賴前端隱藏。
  • 易用性：新增任務及回覆邀請流程短且明確；狀態需同時使用文字與視覺提示。
  • 響應式：支援桌面與手機常見螢幕尺寸。
  • 可用性：表單欄位需驗證必填值、日期與時間邏輯，並提供清楚錯誤訊息。
  • 通知可靠性：需保存通知紀錄並提供失敗重試／監控策略（實作規格待定）。
  • 無障礙：互動控制項支援鍵盤操作與可讀名稱，顏色不可作為唯一狀態提示。

9. 初步驗收標準

  1. 成員只能檢視與自己參與或被指派的任務／行程；未授權項目不可透過直接網址或 API 讀取。
  2. 成員可以建立個人任務並設定截止日期及三種狀態之一。
  3. 管理者可以建立團隊任務、指定負責人並設定截止日期及狀態。
  4. 負責人更新狀態後，任務清單及總覽摘要一致更新。
  5. 行程建立者可邀請多位團隊成員。
  6. 受邀者可接受或婉拒；未回覆者顯示待回覆。
  7. 建立者可查看邀請名單及各參與者狀態。
  8. 任務指派與行程邀請會產生系統內與電子郵件通知紀錄（實際寄送整合另行驗收）。
  9. 新增、編輯表單對必填欄位及不合法日期時間提供驗證提示。
  10. 主要流程可在桌面及手機版介面完成。

10. 指標（建議，目標值待建立基準）

  • 每週活躍團隊／成員比例。
  • 任務指派後的按期完成率。
  • 任務逾期率及平均逾期天數。
  • 行程邀請回覆率與平均回覆時間。
  • 通知送達率及失敗率。
  • 新增任務與回覆邀請的流程完成率。

11. 待確認事項與建議

  1. 角色與管理權限：是否只有一位管理者？管理者能否看見所有團隊項目、管理成員、變更負責人或刪除項目？
  2. 任務協作：是否需要描述、優先級、標籤、附件、留言、子任務或多位參與者？
  3. 行程邀請：成員是否可建立團隊共享行程？要不要支援位置／會議連結、行程衝突提示及重複行程？
  4. 通知規則：截止日前多久提醒？逾期是否重複提醒？哪些項目變更需要重新通知？使用者可否關閉電子郵件通知？
  5. 帳號與團隊生命週期：如何註冊、邀請、移除成員及處理離職成員建立的資料？
  6. 日期與時間：預設時區是否為 Asia/Taipei？是否需要跨時區支援？
  7. 外部整合：第一版是否需要同步 Google／Outlook 行事曆或使用登入整合？
  8. 部署與營運：目標平台、瀏覽器支援、資料保存／刪除政策及備份要求為何？

附錄 A：本版已確認的需求來源

  • 系統需供團隊共同使用。
  • 成員檢視範圍為自己參與及被指派的項目。
  • 任務需要負責人、截止日期與進度狀態。
  • 只有管理者能指派團隊任務；成員可建立個人任務。
  • 行程需支援共享及邀請成員。
  • 行程受邀者需回覆；初步狀態包含接受、婉拒、待回覆。
  • 任務狀態採未開始、進行中、已完成即可。
  • 任務指派及行程邀請需要系統內通知與電子郵件通知。
